## GitHub Pagesにテスト公開する

1. **本番の原稿・バックアップ・パスフレーズをリポジトリに入れない。**
2. 新規リポジトリを作り、**ZIPの中身**をリポジトリ直下に置く（ZIPのままではない）。
3. Settings → Pages → Deploy from a branch → `main` / `/(root)` → Save。
4. 公開URLを**必ずHTTPS**で開く。
5. iPhoneはSafariから「ホーム画面に追加」。
6. テスト用の作品で、PC→iPhone、iPhone→PC、オフライン復帰、競合コピーを確認。

## アプリ内の操作

1. ヘッダーの「☁ 同期を設定」を開く。
2. Firebase Authenticationで作ったメールアドレス・ログインパスワードを入力。
3. **別の、長い原稿暗号化用パスフレーズ（12文字以上）を設定。** これは最初のログイン時に暗号化鍵の検証値をクラウドへ保存し、以後は全端末で同じパスフレーズを入力します。初期設定後の変更機能はまだありません。
4. 「ログイン・暗号化同期を開始」。メモや作品の実データは**暗号化してから**クラウドへ送る想定です。
5. ログイン・鍵入力が成功した状態では、ローカル保存後に自動送信し、画面再表示時・オンライン復帰時・約2分ごとに更新を確認します。
6. アプリを再起動して**暗号化鍵を入力するまでは同期しません**。端末内執筆は可能です。

## 重要な制限・セキュリティ

- **実機のFirebaseと実アカウントでの接続テストは未実施。** 構文チェックと模擬データベースでの暗号化・版管理・競合退避テストは通っています。
- **専門家のセキュリティ監査は未実施。** 未公開の本番原稿を入れないでください。
- 通信前の原稿はWeb Crypto APIのAES-GCMで暗号化しています。PBKDF2-SHA256で原稿専用パスフレーズから鍵を作成します。Firestoreには本文・タイトル・メモ・ルビの平文は保存しません。ただし文書ID・更新時刻・版番号などのメタデータはあります。
- **端末のIndexedDB内のデータは平文です。** 端末ロック、ディスク暗号化、端末のバックアップ管理が必要です。
- 原稿専用パスフレーズを失うとクラウド暗号文から復号できません。Firebaseログインパスワードとは別で、安全な場所に保管してください。私や他人には教えないでください。
- Firestoreの容量、端末容量には限度があります。大長編は1作品1文書のFirestore制限（1MiB）に近づく可能性があります。この試作は暗号文長の上限チェックで止めます。
- オフライン時に本文は端末へ保存しますが、**クラウドへ送信できたとは限りません**。接続を戻してから「☁ 暗号化同期済み」を確認してください。
- 競合が生じた場合は端末側の原稿を「同期競合・保護コピー」として救出し、元の作品IDへクラウド側を反映します。自動の文章マージは行いません。共通メモも競合時は作品メモへコピーして保持します。
- 同期中は作品削除をクラウド上の削除マークとして扱います。通信できない場合や古い版の場合、誤削除を防ぐため削除は止めます。ほかの端末にある原稿を自動で消す処理はまだありません。
- 誤って別のFirebaseユーザーと紐付けないよう、端末ごとに最初に同期したユーザーIDを記録し、別アカウントとの同期は拒否します。
- GitHub PagesのアプリのHTML/JSは公開されます。**公開リポジトリに原稿、メールログインパスワード、暗号化パスフレーズを入れないでください。**
- GitHub Pages上のコード改ざん、悪意ある拡張機能、端末への不正アクセス、フィッシング等の危険はこの暗号化では防ぎきれません。

## 推奨テスト順序

- 初回ログインと、暗号化済みのデータがFirestoreで `iv` と `ciphertext` になっていること（本文の平文が無いこと）
- 別端末で同じ暗号化パスフレーズを使い、ダミー文章を読めること
- PCで書いたあとiPhoneが取り込めること
- オフラインで編集し、オンライン復帰後に同期できること
- PC・iPhoneで意図的に別の編集を行い、競合保護コピーが残ること
- 文章・ルビ・メモ・PDF/DOCX/TXT書き出しが従来どおり動くこと
- ログアウト後、端末内の原稿は残り、クラウド送受信は止まること

**本番用としての安全性を確かめるには、実機・実Firebaseの動作検証とコードの第三者レビューを行ってください。**
